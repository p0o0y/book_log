# Phase 4 — 서재 검색/정렬 + 대시보드 데이터 정합성

> 시작 전 [README.md](README.md)의 공통 컨텍스트를 읽을 것. **선행 조건: Phase 1 완료** (저장소 계층 사용).

## 오버뷰

서재(`/`)는 상태 필터와 책장/그리드 뷰 전환만 지원한다. 책이 늘어나면 원하는 책을 찾기 어려우므로 **검색과 정렬**을 추가한다. 또한 대시보드(`/dashboard`)는 연도 `"2026"`과 월 라벨 `1월~7월`이 하드코딩되어 있어 시간이 지나거나 데이터가 바뀌면 틀린 화면이 된다 — 현재 날짜 기준으로 동적으로 계산하게 고친다.

**구현 방침**
- 서재의 기존 패턴을 따른다: 필터/뷰 상태를 URL searchParams로 관리하는 서버 컴포넌트 방식. 검색(`q`)·정렬(`sort`)도 searchParams로 추가해 필터·뷰와 조합 가능하게 한다. 검색 인풋은 작은 클라이언트 컴포넌트로 분리해 입력 시(디바운스 또는 제출 시) URL을 갱신.
- 정렬 옵션: 최근 추가/완독일순(기본), 제목순, 저자순. 정렬 기준이 없는 책(날짜 없음)은 뒤로.
- 검색은 제목·저자 대상 부분 일치(대소문자 무시).
- 대시보드: 올해 = `new Date().getFullYear()`, 월별 그래프는 1월부터 현재 월까지 동적 생성. "이번 달 완독", "연간 목표 대비" 같은 지표 추가는 선택 사항.
- 검색 결과 0건일 때 빈 상태 메시지 표시.

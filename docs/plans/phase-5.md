# Phase 5 — UX 폴리시: 로딩 · 에러 · 빈 상태 · 피드백 · 접근성

> 시작 전 [README.md](README.md)의 공통 컨텍스트를 읽을 것. **선행 조건: Phase 1~4 완료** (동작하는 기능들에 대한 마감 품질 작업이므로).

## 오버뷰

기능이 갖춰진 앱에 마감 품질을 더한다: 라우트별 로딩/에러/404 처리, 액션 성공·실패 피드백(토스트), 제출 중 버튼 상태, 데이터가 없을 때의 빈 상태 화면, 키보드 접근성. 새 기능 추가 없이 기존 플로우의 완성도를 올리는 단계다.

**구현 방침**
- Next.js App Router의 라우트 파일 컨벤션(`loading.tsx`, `error.tsx`, `not-found.tsx`)을 활용한다. ⚠️ 이 프로젝트의 Next.js 버전은 컨벤션이 다를 수 있으니 `front/node_modules/next/dist/docs/`에서 해당 문서를 먼저 확인할 것.
- 토스트: 외부 라이브러리를 추가하기보다 기존 UI 컴포넌트 스타일(`front/src/components/ui/`)에 맞는 경량 토스트를 직접 구현하거나, 추가한다면 최소 의존성으로.
- 제출 중 상태: `useFormStatus` 등으로 제출 버튼 비활성화 + 로딩 표시 (중복 제출 방지).
- 빈 상태: 서재에 책이 하나도 없을 때 / 필터 결과 0건 / 독후감 0건일 때 안내 + 행동 유도 버튼(예: "첫 책 등록하기").
- 접근성: 별점 입력 키보드 조작, 아이콘 전용 버튼에 `aria-label`, 폼 에러의 스크린리더 연결 정도의 기본 수준을 목표로 한다.

# GitHub 이슈 생성

아래 내용을 바탕으로 GitHub 이슈를 작성하고 `gh` CLI로 생성하라.

## 생성할 이슈

$ARGUMENTS

## 진행 절차

1. **사전 확인**: `gh repo view`로 현재 저장소와 `gh auth status`로 인증 상태를 확인한다. 리모트 저장소가 없으면 이슈를 만들 수 없으므로 사용자에게 알리고 중단한다.
2. **컨텍스트 조사**: 이슈 내용과 관련된 코드·파일을 탐색해 본문에 정확한 파일 경로와 현재 동작을 담는다. 버그라면 재현 경로를, 기능이라면 관련 기존 구현을 파악한다.
3. **유형 판별**: 내용이 버그인지, 기능 요청인지, 개선/리팩터링인지 판별해 제목 접두어와 라벨을 정한다.
4. **초안 작성**: 아래 형식으로 이슈 초안을 작성해 사용자에게 먼저 보여준다.
5. **생성**: 사용자가 승인하면 `gh issue create --title "..." --body "..."`로 생성하고, 생성된 이슈 URL을 알려준다. 라벨은 저장소에 존재하는 것만 사용한다(`gh label list`로 확인).

여러 개의 독립적인 문제가 섞여 있으면 이슈를 나눠 각각 생성할지 사용자에게 물어본다.

## 이슈 형식

**제목**: `[Bug]` / `[Feature]` / `[Chore]` 접두어 + 50자 이내 요약 (한국어)

**본문 템플릿**:

```markdown
## 배경
<왜 이 작업이 필요한지, 현재 상태와 문제점. 관련 파일 경로 포함>

## 작업 내용
- [ ] <구체적이고 검증 가능한 작업 단위>

## 완료 조건
- [ ] <완료 후 실제로 확인해야 할 동작>
- [ ] lint 및 타입 체크 통과

## 참고
<관련 코드 경로, 기존 패턴, 주의사항, 관련 이슈/PR 링크>
```

**작성 원칙**:
- 이슈만 읽고 다른 맥락 없이 작업을 시작할 수 있을 만큼 구체적으로 쓴다
- 버그는 "재현 방법 / 기대 동작 / 실제 동작"을 배경에 포함한다
- 추측한 내용과 확인한 사실을 구분해 표기한다
- 본문은 한국어로 작성한다

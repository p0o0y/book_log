# GitHub 이슈·PR 컨벤션

- 이슈/PR 본문은 한국어로 작성한다.
- 라벨은 저장소에 이미 등록된 체계만 쓴다: 유형(기능|테스트|리팩터링|수정|문서화), 복잡도(낮음|중간|높음), 영역(프론트엔드|백엔드|DevOps). 확실하지 않으면 `gh label list`로 확인하고 임의로 새 라벨을 만들지 않는다.
- 이슈를 해결하는 커밋/PR은 본문에 `Closes #N`을 포함해 이슈와 연결한다.
- 코드를 실제로 수정하는 작업(이슈 해결, 기능 구현)은 착수 전에 계획을 보여주고 **사용자 승인을 받은 뒤에만** 진행한다. 이슈 생성이나 분해처럼 코드를 건드리지 않는 작업은 결과 초안을 보여주고 승인받은 뒤 실행(`gh issue create` 등)한다.
- PR 생성 전에는 항상 사용자에게 확인받는다.
